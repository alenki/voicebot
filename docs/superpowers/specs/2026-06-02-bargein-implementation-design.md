# Barge-in Implementation (Ева, M3) — Design

**Date:** 2026-06-02
**Parent spec:** `2026-06-02-streaming-bargein-design.md` (Roadmap item 5). This document
refines milestone **M3 — Barge-in** for the streaming server *as it actually exists today*,
which has evolved past that plan's Task 8.

## Why a new design

The parent plan's Task 8 assumed the M2 server, where a reply was voiced by a simple
`speak()` loop and `player.stop()` was enough to silence Ева. The shipped
`stream-server.mjs` is different: a reply is generated by a **streaming LLM** (`askStream`)
whose chunks are turned into completed sentences and voiced through a promise chain
(`ttsChain`) that, for each sentence, synthesizes PCM and calls `player.enqueue()`.

Consequence: **stopping the player is not enough.** If the caller interrupts, the next
sentence in the chain finishes synthesizing a moment later and re-fills the player — Ева
goes quiet for a beat and then **resumes talking**. Real barge-in here requires cancelling
the in-flight generation, not just flushing the player. That cancellation mechanism is the
substance of this design.

Current gap in code: STT runs continuously the whole call, but `onPartial`
(`stream-server.mjs`) returns early whenever `state !== "LISTENING"`, so partials produced
while Ева speaks are ignored and she can never be interrupted. `bargein.mjs`'s
`isSubstantive()` exists and is unit-tested but nothing calls it for interruption.

## Goal

While Ева **has the floor** — speaking the greeting, generating a reply (THINKING), or
speaking a reply (SPEAKING) — a *substantive* caller utterance interrupts her: she stops
within a beat and **does not resume**, and her words are not lost (they become the next
turn). Short backchannels ("угу", "да-да") do **not** interrupt. The turn-based stack
(`server.mjs`) is untouched.

Decisions taken with the user:
- **Interruptible anytime she has the floor** — greeting + THINKING + SPEAKING. Interrupting
  during THINKING also aborts the soon-to-be-wasted LLM reply.
- **Offline proof required** — the cancellation logic is extracted into a testable unit and
  covered by deterministic tests that prove "stops and stays silent". Live barge-in is
  human-verified by the user via a real call (only they can place one).

## Chosen approach — cancellation token on a small `Speaker` unit

Of three options:

1. **Cancellation token on a `Speaker` unit (CHOSEN).** Extract the audio tail (synthesize a
   sentence → enqueue to the player) into a tiny `Speaker` that voices sentences under a
   per-turn token. Barge-in flips the token *and* stops the player, so every queued or
   still-synthesizing sentence becomes a no-op — she cannot resume. The interrupt also
   aborts the turn's LLM request. The `Speaker` is pure I/O glue, unit-testable with fakes.
2. **Just stop the player (parent plan Task 8).** Rejected — written for the M2 loop; on the
   streaming-LLM code Ева resumes talking. This is the trap that makes M3 non-trivial here.
3. **Tear down STT + session on interrupt and rebuild.** Rejected — heavy-handed, discards
   live STT context, and loses the very words the caller interrupted with.

Approach 1 isolates the one genuinely-tricky behavior (cancel-and-don't-resume) into a unit
that can be proven offline, and leaves the rest of the working server intact.

## Architecture & components

The change is additive to the streaming path; the turn-based stack is not touched.

**New file — `speaker.mjs`:** a `Speaker(player, synth)` that voices sentences one at a time
under a turn token.

- `begin()` → starts a new speaking turn, returns its token.
- `say(token, text)` → appends to an internal serialized chain a step that synthesizes
  `text` and enqueues the PCM to the player — **but only while `token` is still current**.
  The token is checked both *before* synthesis and *after* (synthesis is async; an interrupt
  can land mid-synthesis, and the resulting audio must be dropped, not played).
- `drain()` → awaits the current chain (used by the caller to know voicing is done/flushed).
- `abort()` → invalidates the current token (so all pending/in-flight `say` steps no-op) and
  calls `player.stop()` (flushes already-queued PCM). This is the single "go silent" action.

`Speaker` depends only on a `player` (`{ enqueue, stop }`) and an async `synth(text)`. It
holds no knowledge of WebSockets, STT, or the LLM — which is what makes it testable.

**New file — `speaker.test.mjs`:** deterministic offline proof, with a fake player (records
enqueue calls) and a controllable fake synth (promises the test resolves on demand):
- *Normal completion:* three sentences → three enqueues, in order.
- *Stops and stays silent (the core proof):* begin a turn, queue several sentences with synth
  held pending; `abort()` after the first enqueue; then resolve the remaining synths →
  assert `player.stop()` was called and **no further enqueue happened**.
- *Fresh turn after abort:* `begin → say → abort → begin → say` → the new turn's audio is
  enqueued (abort doesn't wedge the Speaker).

**Edit — `bargein.mjs`:** keep `isSubstantive` as-is; add the barge-in **policy**:

```
shouldInterrupt(state, partial, sinceFloorMs, graceMs) =
  (state === "SPEAKING" || state === "THINKING")   // bot has the floor
  && sinceFloorMs >= graceMs                        // past the grace window
  && isSubstantive(partial)                         // substantive, not a backchannel
```

Pure function. The caller additionally suppresses a partial that merely equals the caller's
*last finalized* utterance (echo of the turn that just ended) — passed in or checked at the
call site.

**Edit — `bargein.test.mjs`:** add `shouldInterrupt` cases — fires on substantive speech in
SPEAKING/THINKING past grace; does not fire in LISTENING, within the grace window, or on a
backchannel.

**Edit — `speech.mjs`:** `askStream` accepts an abort signal and forwards it to `fetch`, so
an interrupt during THINKING cancels the LLM request. Signature becomes
`askStream(messages, onChunk, { model, signal } = {})`; the one call site is updated. When
the fetch is aborted, `askStream` rejects (AbortError) — the caller treats that as "turn
cancelled", not an error.

**Edit — `stream-server.mjs`:** wire the above into the per-call session.
- Construct one `Speaker` per call over the existing `PacedPlayer` and a logging `synth`
  wrapper (preserves the current one-retry + "TTS пропуск" log).
- `handleTurn` and the greeting `speak()` voice their sentences via `speaker.say(token, …)`
  instead of the inline `ttsChain`.
- Add `floorAt` (timestamp the bot took the floor — set when greeting starts and at the top
  of `handleTurn` when `state` becomes THINKING) and `lastFinalText` (the caller's last
  finalized utterance, for the echo guard).
- Hold the turn's `AbortController` in a session var (`currentTurn`) so `interrupt()` can
  abort the LLM.
- Rewrite `onPartial`: when `SPEAKING`/`THINKING`, evaluate `shouldInterrupt(...)` (+ echo
  guard) and call `interrupt(partial)` if it passes; otherwise ignore. LISTENING behavior
  (endpoint arming) is unchanged.
- `interrupt(partial)`: log `BARGE-IN`; `currentTurn?.abort()` (cancel LLM);
  `speaker.abort()` (silence audio, no resume); `beginListening()` (state reset); then seed
  `pendingPartial = partial` and `armEndpoint()` so the same STT stream finalizes the
  interrupting utterance as the next turn.
- `handleTurn` end: if the turn was aborted (its `AbortController` signal is aborted), record
  the portion Ева actually voiced to history (best-effort dialog coherence) and **return
  early without `beginListening()`** (interrupt already set LISTENING) and without speaking
  the error apology.

## Data flow (barge-in path)

```
caller speaks while Ева has the floor
  → STT (always running) emits a partial
  → onPartial: SPEAKING/THINKING + shouldInterrupt(...) + not an echo?  ── no ──► ignore
                                   │ yes
                                   ▼
                              interrupt(partial)
        ┌──────────────┬───────────────┬──────────────────────────┐
   abort LLM       Speaker.abort()   state → LISTENING        seed endpoint with
 (currentTurn)   (token void +       (+ turn reset)           `partial`; armEndpoint()
                  player.stop())                                     │
                                                                      ▼
                                          same STT stream finalizes the utterance
                                                → handleTurn(new turn) → Ева answers it
```

The in-flight `handleTurn` for the interrupted turn unwinds harmlessly: its `say` steps
no-op (stale token), its `askStream` rejects with AbortError (caught and ignored), and its
end-check sees the aborted signal → records what was voiced, returns without re-entering
LISTENING.

## Behavior details, guards, and their rationale

- **Grace window (~500 ms, tunable):** suppresses false interrupts from the caller's own
  trailing words right after their turn finalizes (our self-endpointing can finalize before
  STT stops emitting partials for that same utterance). Measured from `floorAt`. The parent
  spec already classes barge-in thresholds as first-guesses tuned on real calls.
- **Echo guard:** ignore a partial that equals `lastFinalText` — defends the same boundary
  from a different angle (a stale partial identical to the just-finalized turn).
- **No audio lost:** the interrupting partial seeds the endpoint logic, so the still-running
  STT stream surfaces the full utterance as the next `finalizeTurn` — exactly the parent
  spec's "the interrupting utterance flows into the next turn" property.
- **History on interrupt:** push the sentences Ева actually voiced before the cut (best
  effort), not the full intended reply. Keeps the model's view roughly aligned with what the
  caller heard. Tunable; a defensible default for the spike.
- **Echo / self-barge-in:** unchanged from the parent spec — Voximplant streams only the
  caller's leg (confirmed in M0), so Ева never hears herself; no acoustic echo cancellation.

## Error handling & lifecycle

- **Interrupt during THINKING:** `askStream` fetch is aborted → rejects AbortError → caught,
  recognized as a cancel (signal aborted), returns quietly. No apology spoken, no double
  state transition.
- **Synthesis error on an interrupted sentence:** already a no-op (stale token); existing
  one-retry + skip-and-log behavior is preserved for non-interrupted sentences.
- **WebSocket close mid-reply:** unchanged — `ws.on("close")` closes STT and stops the
  player; `Speaker.abort()` semantics make any in-flight `say` harmless.
- **Spurious/rapid interrupts:** `interrupt()` is idempotent in effect — a second call while
  already LISTENING does nothing harmful (no active speaking turn, abort on a settled
  controller is a no-op).

## Verification

- **Offline (agent-runnable, shown as output):**
  - `node --test speaker.test.mjs` — the stop-and-stay-silent proof + normal + post-abort.
  - `node --test bargein.test.mjs` — `isSubstantive` (existing) + `shouldInterrupt` (new).
  - `node --test playback.test.mjs` — unchanged, confirms the player still drains/stops.
  - `node --check stream-server.mjs speech.mjs bargein.mjs speaker.mjs`.
- **Regression:** the streaming greet→answer loop must still work; the turn-based
  `node verify-eva.mjs` path is unaffected (no `server.mjs` change).
- **Live, user-verified (cannot be claimed working without a real call):** interrupt Ева
  mid-sentence with a real phrase → she stops within a beat, the server logs `BARGE-IN`, and
  she answers the new turn; say "угу" while she talks → she keeps going, no `BARGE-IN`.
  (Parent spec M3 pass criteria.)

## Review outcome (2026-06-03)

An adversarial multi-lens review + an independent concurrency/state audit confirmed the core
invariants CLEAN: no-resume (Speaker token checked before & after synth), no-stuck-state
(every floor-taking path returns to LISTENING), no-double-listen (abort guards), no-lost-
utterance (interrupting partial seeded as next turn), and lifecycle (timers, AbortController,
ws-close). One real bug was found and fixed: `isSubstantive` rated all-backchannel multi-word
partials ("ну да", "ага угу", "да-да-да") as substantive — now excluded (hyphen-aware).

Two detection-tuning edges were noted and **deferred to the real-call tuning pass** (they do
not break the contract and changing them blind risks regressions):
1. The echo guard is exact-match (`t !== lastFinalText`); a verbatim repeat by the caller
   would not interrupt. Mitigated in practice: partials grow word-by-word, so an interrupt
   fires on an earlier partial before the full string matches.
2. `floorAt` (grace start) is set at THINKING start; a slow LLM can consume the 500 ms grace
   before Ева is audible. Mitigated: finalization implies the caller already paused, so no
   live trailing speech remains by then. (Re-anchoring grace to the first audible frame was
   considered and rejected: it would extend the grace window into Ева's actual speech and
   make her *harder* to interrupt in her first 500 ms — the opposite of responsive barge-in.)

### Update 2026-06-03 — finishable part landed, tuning still gated on a live call

- The echo gate was folded from the `stream-server.mjs` call site into the pure
  `shouldInterrupt(..., lastFinalText)` policy (behavior-preserving) so the whole decision is
  unit-tested in one place (`bargein.test.mjs`). No runtime behavior changed.
- `stream-server.mjs` now logs **suppressed near-interrupts** — a substantive partial that
  arrived while Ева had the floor but did *not* interrupt — as `barge-in подавлен [грейс …|эхо …]`
  with the `sinceFloor` timing. These lines are exactly the data the tuning pass needs to
  choose `GRACE_MS` and judge the echo gate.
- The two edges above remain **deferred**: both want real-call log values, and changing them
  blind risks regressions (the agent cannot place a call). Next live call: skim the
  `barge-in подавлен` lines and tune from observed `sinceFloor` / echo frequencies.

## Out of scope

- Streaming TTS (v3 gRPC) — still the post-spike follow-up.
- Tuning the grace window / backchannel list / `isSubstantive` thresholds beyond a first
  reasonable guess (done on real calls).
- Acoustic echo cancellation (not needed — only the caller's leg streams in).
- Any change to the turn-based `server.mjs` / `/reply` path.
